# 意图识别与目标提取项目技术报告

更新日期：2026-03-31

## 1. 项目目标

本项目面向课堂指令场景，完成两项串联任务：

1. 意图识别（`action`）：`继续` / `提问` / `回答` / `讨论` / `举手表决`
2. 目标提取（`target`）：从固定人名集合中抽取执行动作对象（最多 3 人）

最终输出结构：

```json
{
  "action": "",
  "target": []
}
```

## 2. 技术栈与运行环境

- Python 虚拟环境：项目内 `.venv`
- 依赖版本：
  - `scikit-learn==1.8.0`
  - `pandas==3.0.1`
  - `joblib==1.5.3`
- 算法范式：传统机器学习（TF-IDF + 线性分类器），CPU 可训练与推理

## 3. 系统架构

主流程采用二阶段串联：

1. 文本进入意图分类模型（`intent_model.joblib`）
2. 同步进入目标提取器（规则 + 二分类模型）
3. 流水线规则做最终纠偏，输出统一结果

关键模块：

- `train.py`：训练意图模型
- `target_train.py`：训练目标候选二分类模型
- `target_extractor.py`：候选召回、规则抽取、模型判别
- `pipeline.py`：意图与目标融合与业务规则兜底
- `run_pipeline.py`：CLI 推理入口

## 4. 模型设计

### 4.1 意图识别模型

- 文本特征：`TfidfVectorizer(analyzer='char', ngram_range=(1,3), sublinear_tf=True)`
- 分类器：默认 `LinearSVC(C=1.0, dual='auto')`（可选 `LogisticRegression`）
- 训练逻辑：
  - 自动检查样本量与类别分布是否可做分层验证
  - 满足条件时执行 `train_test_split` 并输出 `classification_report`
- 推理增强（`pipeline.py`）：
  - 关键词提示词纠偏（提问/回答/讨论/表决/继续）
  - 当模型分数边际（top1-top2）低于阈值 `0.2` 且无强提示词时，回退为 `继续`

### 4.2 目标提取模型

- 候选召回：从 `people.json` 的别名列表中做字符串匹配，按出现顺序去重
- 高精度规则优先：
  - `讨论/交流/商量`：多人共同目标
  - `帮/帮助/协助`：优先抽取动作发起人（帮助者）
  - “姓名 + 你/同学你”直接称呼：抽取该姓名
  - 评价型句式首名优先规则
- 规则未命中时使用二分类模型：
  - 特征模板：`句子 + 候选名 + 局部上下文(左右8字符) + [TARGET]标记句`
  - 分类器：`LogisticRegression(liblinear, max_iter=2000)`
  - 阈值：`predict_proba >= 0.5` 判为目标
- 输出约束：最多 3 个目标

### 4.3 流水线业务规则

- `回答` 必须有目标；若目标为空，降级为 `提问`
- 志愿者招募句（如“谁来/谁愿意/哪位同学”）统一修正为 `提问` 且空目标
- 反馈性评价句（如“答得很好/不错”）统一修正为 `继续`
- `回答` 类仅保留首个目标，且遇到“某某的问题”引用句式可降级为 `提问`

## 5. 数据与标注

数据文件：

- 意图数据：`data/intent_train.example.csv`
- 目标数据：`data/target_selector_train.example.csv`

对象标注规范见 `docs/OBJECT_LABELING_GUIDE.md`，核心原则为：

- 只标注“执行动作的人”
- 被帮助者/被提及者通常标 0
- 讨论类允许多目标
- 单句可含正负混合样本（`text,name,label`）

固定对象集（当前 6 人）由 `people.json` 管理，支持 `aliases` 扩展。

## 6. 训练产物与性能

### 6.1 意图模型（`models/intent_metrics.json`）

- 样本数：257
- 标签数：5
- 验证集准确率：**0.9423**
- 宏平均 F1：**0.9202**
- 加权 F1：**0.9389**

观察：

- `回答`、`讨论` 识别效果较高
- `继续` 与 `举手表决`召回相对偏弱（support 较小）

### 6.2 目标模型（`models/target_selector_metrics.json`）

- 样本数：345（正样本 140，负样本 205）
- 验证集准确率：**0.8696**
- 正类（label=1）：
  - Precision：**0.7879**
  - Recall：**0.9286**
  - F1：**0.8525**

观察：

- 模型倾向提高正类召回，能较好避免漏抽取
- 正类精度仍有提升空间，需通过规则和数据进一步抑制误报

## 7. 快速验收结果

执行命令：

```powershell
.\.venv\Scripts\python.exe run_pipeline.py --intent-model models/intent_model.joblib --target-model models/target_selector.joblib --people-config people.json --text "张晓丹你和丽娃讨论一下这个问题。" --text "这道题其实不难，关键在于理解条件。"
```

返回结果：

- 样例1：`讨论`，目标为 `["张晓丹","丽娃"]`
- 样例2：`继续`，目标为空 `[]`

与预期一致，主流程可用。

## 8. 工程化情况

优点：

- 训练、推理、配置分离清晰
- 模型指标、元数据自动落盘，便于追踪
- 规则层可解释性强，适合小样本业务快速迭代

当前不足：

- 缺少自动化测试（单元测试/回归测试集）
- 缺少批量评测脚本与混淆矩阵可视化
- 缺少模型版本管理和阈值自动校准机制

## 9. 风险与优化建议

1. 数据规模偏小且类别分布不均，建议补齐长尾类别（尤其 `举手表决`、`继续` 边界句）。
2. 当前目标抽取依赖固定人名集合，对新名字泛化弱；建议增加“未知实体”处理策略。
3. 可建立固定离线评测集，按版本输出：
   - 意图 macro/weighted F1
   - 目标抽取 P/R/F1（按句级与实体级）
4. 建议补充端到端回归用例，覆盖关键业务规则（回答降级、志愿者问句、帮助句式、多人讨论）。
5. 后续可引入概率校准或阈值搜索，提高目标抽取 precision 与 overall stability。

## 10. 结论

该项目已形成一套可部署的轻量化中文课堂指令理解链路，具备可解释、低资源、可快速迭代的优势。在当前样本规模下，意图识别表现较好（Acc 94.23%），目标提取达到可用水平（Acc 86.96%，正类召回高）。下一阶段重点应放在数据扩充、评测自动化和误报抑制上，以提升线上稳定性与泛化能力。
